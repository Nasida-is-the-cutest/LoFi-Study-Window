## 实现结果

进入普通房间后，游戏自动显示置顶学习小窗。默认显示静态房间背景、原番茄钟的大号中文计时及暂停／继续、动画／静态、原窗口按钮。窗口支持拖动、缩放和位置记忆。静态模式暂停房间相机绘制，音乐和计时继续；动画模式保留低帧率房间画面。

本次修复还包括后台导出线程、镜像资源释放、窗口归属验证、设置页重复注册与异常恢复、删除确认失败处理及卸载恢复。具体使用和安装步骤见 [LEARNING_WINDOW.md](LEARNING_WINDOW.md)。

此次主插件重新构建成功，0 警告、0 错误，165 项回归全部通过。使用工作区独立游戏副本中的 UI 预览探针，在游戏启动业务之前阻止 Boot，调用实际插件的界面构建方法；以固定计时文字、测试背景和 Windows 中文字体检查布局。720×405、480×270、320×180、480×900 四种尺寸的截图均无重叠或裁切，三个按钮的实际 UI 射线命中正确，顶部说明对象不存在。点击测试检查了预览中的标签变化和回调区域；它使用模拟回调，不作为原番茄钟业务的新验收。

## 计时精度

低帧率及窗口切换测试曾观察到使用原 `Time.deltaTime` 推进时，偏差超过 1 秒。改进版将系统单调时钟的增量送入原计时服务，并在暂停、继续、跳过和重置边界重新同步。仍使用原游戏完成判断与后续业务处理。

完整 25 分钟工作加 5 分钟休息测试已通过：工作阶段实际 1500.175 秒，休息阶段实际 300.109 秒；误差分别为 +0.175 秒、+0.109 秒，合计 +0.284 秒，均满足不超过 1 秒的要求。参考计时为独立 `Stopwatch`，每帧只推进原服务一次。测试过程中包含窗口切换、全屏恢复、竖窗、动画、设置页操作及最小化。

长测试开始后，最终构建又修正了窗口丢失恢复和静态视图的角色点击输入。已逐方法比较计时补丁和高精度计时工具（含编译器生成方法）的 26 个方法的编译指令，确认这些计时方法一致；最终 DLL 另做启动及功能检查。哈希与最终结果见 [validation-results.json](validation-results.json)。

最终 DLL 的独立 2+2 秒运行检查分别为 2.096 秒和 2.098 秒。静态与动画模式中的后台角色点击均被阻止，返回原窗口后原点击逻辑重新启用；这修复了静态相机关闭后原角色点击方法出现空相机异常的问题。

探针曾出现一次命令文件读写共享冲突，下一次轮询恢复；这是测试通信的异常，不属于交付插件。另一次以隐藏方式启动的测试副本在恢复原隐藏窗口后停止处理探针命令，该进程已结束；以正常可见启动方式重验后，窗口恢复与卸载通过。随后修正恢复逻辑：从可见学习小窗返回时显示原游戏窗口。隐藏启动后恢复和卸载均已重新通过，窗口可见且计时／探针继续运行；原三参数窗口恢复接口保留。

## 电池功耗验收方法

**按用户要求，本阶段先完成代码和功能验证，电池功耗测试延期。20% 目标尚未验收。**

目标是同机同条件下，新版默认静态小窗的平均整机电池放电功率比原版 PiP 至少降低 20%。每种模式各做三次，组成三对；每次预热 2 分钟、记录 10 分钟，共约 72 分钟，另留切换时间。

保持亮度、电源模式、实际 GPU、窗口大小、场景、音乐、音量和后台程序一致；旧版也使用同样大小的小窗。每对之间退出游戏再更换 DLL，避免同时运行两份游戏。新旧分别使用独显和核显的数据不可直接用来证明 MOD 的功耗效果。

脚本通过 Windows 电池仪表读取放电功率与剩余能量，拒绝插电、无效功率、提前退出、记录不足以及条件变化。优先使用整段能量差计算平均 W；不足时使用时间加权功率积分，并要求每对方法一致。电池仪表存在精度和采样延迟限制。

```powershell
# 启动原版 PiP，确认同等条件后，使用电池运行。
pwsh -File scripts/Measure-LearningPower.ps1 -Mode BaselinePiP -Pair 1 -GameDirectory '测试游戏目录'
# 退出游戏、更换改进版 DLL，进入相同场景的静态小窗。
pwsh -File scripts/Measure-LearningPower.ps1 -Mode LearningStatic -Pair 1 -GameDirectory '测试游戏目录'
# 完成 Pair 2、Pair 3；第二对可先测新版以降低顺序偏差。
pwsh -File scripts/Compare-LearningPower.ps1 -ResultsDirectory power-results
```

`summary.json` 给出每对及总体平均功率、降低比例和 20% 判定。三对有效数据齐全后再得出结论。
